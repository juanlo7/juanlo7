## `C:\> experience`

**Software Engineer · STEL Order**<br>
<sub>November 2025 — present · Murcia, Spain · Part time, alongside the degree</sub>

`Java 21` `Spring Boot` `Spring Data JPA` `MySQL` `Flyway` `Gradle` `React` `TypeScript` `Formio.js` `Vitest` `Claude Code`

- **Labelling module** <img src="https://img.shields.io/badge/In_production-2EA44F?style=flat-square" alt="In production"><br>
  Built the labelling module from scratch as lead developer, backend to frontend: a visual editor on Konva and labels with barcodes and data from the ERP, printed in batches to PDF.
  <details><summary>More</summary>

  - Five kinds of label (product, customer, incident, sales order and work order), whose fields are filled with the ERP’s data at print time.
  - I moved the editor to Konva: text, barcodes, images, shapes and lines on a canvas, with undo, redo and preview.
  - Seventeen 1D and 2D barcode formats with bwip-js, from EAN-13 and Code 128 to QR, Data Matrix and PDF417, validated against the same table in the editor and at print time.
  - Batch printing to PDF with jsPDF, per stock unit and warehouse, with the same margins as the preview.
  - Five starter templates created for each company the first time it opens the module, named in its language, and per-warehouse permissions.

  </details>
- **Accounting module** <img src="https://img.shields.io/badge/In_staging-D9822B?style=flat-square" alt="In staging"><br>
  Co-lead the accounting module with a teammate, backend and frontend: chart of accounts, journal entries, the general journal, year-end close, taxes and reports.
  <details><summary>More</summary>

  - Journal entries: numbering per financial year on posting, a change history for manual entries, automatic entries that can only be deleted, and blocked accounts rejected.
  - Year-end close with its result entry, and the general journal with export.
  - Integration with the ERP over OpenFeign: I write each bank’s and payment method’s ledger account back to the ERP, and every entry shows the ERP document behind it.
  - Screaming architecture with vertical slices, hexagonal inside each one, enforced by an ArchUnit suite. The backend rejects cookie-authenticated writes from a foreign origin.

  </details>
- **Forms engine** <img src="https://img.shields.io/badge/In_staging-D9822B?style=flat-square" alt="In staging"><br>
  Designed and built end to end a dynamic forms engine with Formio.js: templates and instances linked to the ERP’s business entities, such as sales or customers.
  <details><summary>More</summary>

  - From day one, in November 2025, I set up the workspace, the domain model and the API documented with Swagger.
  - Forms linked to the ERP’s catalogue, customers, sales and technical service, which opens them in an iframe and listens to their messages.
  - On save, each submission goes through a filter chain (Chain of Responsibility) that extracts dropdown values and checks required fields.
  - I set up the API tests with REST Assured and Testcontainers on MySQL, with unit tests for the services and acceptance tests for the controller.

  </details>
- **Microservices.** All three are Java 21 and Spring Boot microservices with hexagonal architecture and DDD, their own MySQL database, Flyway migrations and REST APIs documented with OpenAPI.
- **Legacy monolith.** Integrated them with the legacy Java 8 monolith both ways: the ERP opens each module with a JWT and the module calls the ERP through OpenFeign, as part of the platform’s gradual move to microservices.
- **React components.** Implemented components for the company’s shared React/TypeScript catalogue, such as a generic table with configurable content used by every new microservice.
- **Claude Code agents.** Built the accounting module’s Claude Code agents with my teammate; they review pull requests (architecture, security, queries and tests) against the repository’s own rules.
